# Prototype

Identify the question the prototype should answer and choose the smallest useful experiment. A mockup, existing app route, script, interactive HTML, or native application may fit. Ask when ambiguity would materially change the experiment; otherwise state a useful assumption and proceed.

Keep disposable work recognizable and easy to run, using existing project conventions where helpful. Show the relevant state or result. Add persistence, polish, error handling, and checks only when needed to answer the question or operate the experiment reliably.

Record what was learned and its limits. Implement the finding when the user requested implementation; otherwise deliver the prototype. Follow the project's convention for retaining or removing temporary work, without requiring a branch, issue, or production change for every experiment.

[LOGIC.md](LOGIC.md) and [UI.md](UI.md) offer optional formats for interactive state walkthroughs and multiple visual variants. Read one when that format helps; its artifact shape and workflow are examples to adapt to the task.
